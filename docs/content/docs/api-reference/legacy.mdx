## GET /legacy

<ReferenceGrid>
  <div>
    <ReferenceHeader title="Read the legacy feed" method="GET" path="/legacy" hideTitle={true}>
      This route retains a JSON wrapper around validated RSS-shaped records. New consumers should use /v1.
    </ReferenceHeader>

### Differences from /v1

| Convention | Legacy behavior |
| --- | --- |
| Envelope | A `LegacyDocument` object containing `feed`, not a JSON:API document. |
| Default product | `1` (Unleaded) unless `product` is supplied. |
| Station fields | Hyphenated RSS fields and string prices/coordinates. |
| Enrichment | No provider fields or normalized station enrichment. |
| Expansion | `expand` is rejected, even when empty. |

  </div>
  <CodeRail>

```bash title="Request"
curl 'https://fuelwatch.oss.bhodges.me/legacy?product=1'
```

```json title="Illustrative excerpt"
{
  "feed": {
    "items": [{
      "trading-name": "Example Station",
      "brand": "BP",
      "price": "185.9",
      "date": "2026-09-29",
      "address": "1 Test Road",
      "location": "PERTH",
      "latitude": "-31.95",
      "longitude": "115.86",
      "phone": null
    }]
  }
}
```

  </CodeRail>
</ReferenceGrid>

Channel/parser fields can accompany `items`; this excerpt is not an exhaustive RSS field list. Source descriptions/features may contain combined free text. Source/parser field presence is retained rather than expanded into the normalized DTO. Phone values are normalized to E.164 or null.

The six filters and their aliases work here too, but every query uses source-filtered selection and the 24-combination limit. Multi-product results contain separate station/product items with a numeric `product` marker; a single-product response omits that marker.

The content type is `application/json;charset=UTF-8`. This route does not apply `/v1` JSON:API media negotiation. Success metadata is not the `/v1` `meta` object; source-date/fetch headers remain available. Caching, ETags and HEAD work with a separate representation cache.

Errors use `{"error":{"code":"invalid_query","message":"Unsupported FuelWatch query."}}` and `no-store`. Do not deserialize them as JSON:API errors.

## Migration to /v1

Read `data[].attributes` instead of `feed.items[]`; select a product explicitly if you previously relied on unleaded being the default. Read numeric `price.products["1"]`, numeric coordinates and camelCase fields. Adopt compact codes or request expansion. Preserve source-date/validity checks and optional provider attribution.

No removal date for `/legacy` is declared by this source.
